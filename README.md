# TQA 看课打分台

按 V1.9 评分标准给 AI 课打分（≤6 分和 ≥9 分需写打分原因）、逐条记录需要跟进的问题；管理员看板汇总每日进度、按级别统计和双人一致性；问题同步人把问题批量同步到 Lark 问题反馈池。

- 网页：纯静态页面（`index.html` + `app.js`），由 GitHub Pages 发布。
- 数据与登录：Supabase（项目 `tqa-scoring`，新加坡区）。数据库结构与权限见 `supabase/schema.sql`。
- `config.js` 中的 anon key 是公开给浏览器用的，数据由数据库行级权限保护；不要把 service_role key 放进仓库。

## 角色
- **打分者**：管理员在「设置」里登记邮箱后，打分者首次打开网页选"首次使用 · 设置密码"，之后用邮箱和密码登录。只能看到、修改自己的记录。
- **管理员**：额外可以看看板、管理成员（添加、停用、重设密码、设置对比角色）、修改老师名单和目标范围。

## 修改网页
直接改仓库里的文件，推送到 `main` 分支后 1–2 分钟内生效。

## 专家复评任务
- 数据库每天北京时间 07:00（定时任务 `tqa-review-tasks`）在复评日（默认周二到周五）从截止前一天的常规打分里抽课，生成专家复评任务；参数在「设置 → 专家复评任务」。
- 专家在「复评」页打分，保存后任务自动完成；管理员在同一页看每位打分者和每个级别的覆盖情况。
- 数据库脚本：`supabase/review_tasks.sql`（在 `schema.sql` 之后运行，可重复运行）。
- 没有维度分数的记录标"仅留档"，不参与平均分、一致性和抽课。

## V1.9：打分原因、逐条问题与问题同步
- 每个维度可写打分原因，≤6 分和 ≥9 分必填（`scores.reasons`），记录同时保存评分标准版本（`scores.rubric`）。
- 问题逐条记录在 `issues` 表（时间点、问题描述、根因、优先级 P0–P3）；旧记录的文字问题保留在 `scores.issues`。
- 「同步问题」页：同一 Lesson + 同一根因自动归组，复制成问题反馈池的列顺序，标记已同步；已同步过的问题再出现时给出可追加的备注。管理员和勾选了"同步问题"的成员可用，只能看到问题，看不到分数。
- 数据库脚本：`supabase/v19_reasons_issues.sql`（在 `schema.sql` 之后、`review_tasks.sql` 之前运行）。
