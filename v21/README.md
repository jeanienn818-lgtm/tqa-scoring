# TQA Rubric V2.1 打分平台

入口：`https://jeanienn818-lgtm.github.io/tqa-scoring/v21/`

## 启用

1. 在现有 `tqa-scoring` Supabase 项目的 SQL Editor 运行 [`supabase-v21.sql`](supabase-v21.sql)。脚本只新增或重建 `_v21` 对象，不更改 V1.9 的打分、复评或问题数据。运行后确认没有 SQL 错误。
2. 打开 V2.1 入口，使用原账号登录。管理员先检查设置、老师名单和复评参数；这些设置保存在 V2.1 独立配置表中。
3. 用一条实际测试记录核对：8 维打分与原因可保存、我的记录可查看与编辑、看板显示、专家复评任务和问题同步可用。正式使用前删除这条测试记录及其相关问题。

## 打分记录与权限

- 八维打完后，每节课须写 3 条原因：最低分 2 项、最高分 1 项。同分时按维度权重随机抽选；每轮抽选中，15% 维度的权重是 10% 的 1.5 倍。单人或多人打分均各自独立抽选；结果在当前表单中保持稳定，已写的合格原因优先保留。
- 普通打分者只能查看自己的记录、编辑 V2.1 新评分，看不到其他人的分数；管理员可以查看全部分数。导入的历史评分只读。
- 专家在指定课程的复评任务中，完成自己的打分后，可以查看该课程普通打分者的分数和打分原因作对比；打分前看不到。
- 不同账号可以对同一课程链接、同一 Class ID 分别打分。同一账号对同一 Class ID、同一评分标准只能保存一条记录；历史评分不阻止按 V2.1 重新打分。请每位同事使用自己的账号。

## 课程字段与明细导出

- 标记“完课”时必须填写完课日期；标记“未完课”时不填。版本号指课程或产品版本，选填，与评分标准版本 V2.1 分开保存。
- 历史记录缺失的完课日期、课程版本号保持空白；新建或编辑 V2.1 完课记录时须填写完课日期。
- 管理员在“看板”点击“导出全部打分明细 CSV”可导出平台内所有记录，不受看板筛选影响。表格中的“导出当前筛选明细 CSV”仅导出当前评分标准及其他筛选范围。明细包含课程信息、8 维分数与原因、问题和建议。
- 现有 V2.1 数据库升级运行 [`2026-11-09-course-fields.sql`](2026-11-09-course-fields.sql)；新部署的 [`supabase-v21.sql`](supabase-v21.sql) 已包含这些字段。

## 数据边界

- 共用 Supabase Auth、`members` 账号名单及 `tqa-account` 账号服务。因此在 V2.1 修改成员、角色或密码，会影响原平台的登录权限。日常打分不触碰原平台的记录。
- V2.1 的 `scores_v21`、`issues_v21`、`issue_groups_v21`、`review_tasks_v21`、`app_config_v21` 与原平台独立。历史评分只通过 [`2026-11-10-import-v19-completed.sql`](2026-11-10-import-v19-completed.sql) 复制；原表不改动。
- 导入范围是原平台标为“完课”、八维分数完整且有总分的记录。原 `rubric` 为空时在 V2.1 标为“未标注 / Unspecified”，不推断评分版本。看板默认只统计 V2.1，可切换评分标准查看历史；自动复评与对比仅使用 V2.1 新评分。
- 平台右上角可切换中文 / English，选择会在该浏览器中记住。打分页的通用规则、Quick Guide、完整标准以及记录、看板、复评、问题同步、设置页面随之切换。完整 Rubric 链接会打开相同语言。
- 语言只改变界面显示。课程类型、问题根因等保存值保持原样，两种语言登录同一账号、读取同一批 V2.1 数据。
- `rubric.html` 是完整的 V2.1 中英双语 Rubric；打分页按所选语言显示快速指南和完整标准。

## 更新评分标准

`rubric-v21.js` 由 `python3 build-rubric-data.py` 从完整 Rubric 的源数据生成。修改标准后重新运行脚本，避免两种语言与文档不一致。界面文案在 `i18n.js` 中维护。
